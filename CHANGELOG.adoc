=== [Unreleased]

==== Added

* *`uuid_v8` on every registry entry* (standards ADR-008, owner ruling
  D320): the profile C UUIDv8 of `github.com/<owner>/<repo>` in the
  `gv-clade-index` domain. A deed writes it as
  `#u8"gv-clade-index:github.com/<owner>/<repo>"`. The ids come from
  standards' shared generator `scripts/uuid-v8.js`, pinned at `75bd599` and
  sha256-checked by `sync/uuid-v8.sh`, which caches it outside the checkout.
  No copy of the algorithm lives here.
* `uuid` is unchanged, still the UUIDv5 of the same name: `/v1` is
  additive-only (`docs/decisions/0004-api-versioning.adoc`), so the v8 id is
  added beside it. `/v2` makes it the `uuid`. `docs/api/openapi.yaml`
  declares `uuid_v8` (1.1.0). Every other field is byte-identical.

* *ADR 0007: ids follow the forge path.* A move or rename mints new `uuid`
  and `uuid_v8` values from the new path. The earlier ids are written to
  `worker/data/archive.json` for reference only: the file is not loaded into
  KV and no route serves it. The seed gains an optional `former` list
  (`"owner/name@YYYY-MM-DD"`, oldest first), read by `sync/parse-repos.sh`.
  `docs/api/openapi.yaml` 1.2.0 describes the change, an explicit exception
  to the `/v1` additive-only rule for these 2 fields only.

==== Changed

* *ADR 0008: identity is minted once* (owner rulings U1 to U4, 2026-11-11 and
  2026-11-12). It supersedes ADR 0007 and restores the immortal rule of ADR
  0006. `uuid` and `uuid_v8` derive from the birth path, the first `former`
  entry, and a move or rename never changes them.
  `scripts/check-registry.sh` re-derives from the recorded birth path instead
  of the current path, and refuses an entry whose id equals another entry's
  id or a retired id, so a vacated path's id is never minted again.
* *19 birth ids restored.* The 18 repositories reminted under ADR 0007 take
  back the ids of their birth paths (`standards`:
  `d9e987dc-bb7b-51aa-839b-3d8bbfe774c3`) and keep their current locations.
  `burble` records its move from `hyperpolymath/burble` and takes its birth id
  `0a37e17d-8ee5-5c30-9daf-571315a88a84`. The 19 ids they carried until now
  are retired: the seed's new `retired` field lists them, `archive.json`
  records them, and no repository may take one again.
* `worker/data/archive.json` changes shape: each entry has `uuid`, `uuid_v8`,
  `birth`, `former` locations (no ids) and `retired` ids. It is still not
  served. `docs/api/openapi.yaml` 1.3.0 describes the ids.
* `sync/deploy-clade-a2ml.sh` derives a new CLADE record's id from the birth
  path.

* *ADR 0007 accepted* (owner ruling of 2026-11-10). Its status was
  "Proposed" in the ADR and in `docs/decisions/README.adoc`. It now
  supersedes ADR 0006's "`uuid` is immortal" rule, as ADR 0006 already
  records.

* *18 moved repositories recorded* (census of 2026-11-10): the 8 Stealth
  Glider repositories and 9 more (airborne-submarine-squadron,
  befunge93-vault-cracker, blue-screen-of-app, game-server-admin,
  hotchocolabot, megadog, pow-the-game, proof-of-work, thejeffparadox) now
  under `catachresis-colloquium`; `standards` under `metadatastician`.
  Their ids are reminted and their earlier ids archived. Each repository's
  own records still carry the old id until its own follow-up PR.
* *Correction:* the same census also recorded `burble` as moved from
  `metadatastician` to `hyperpolymath`. That was backwards:
  `hyperpolymath/burble` redirects to `metadatastician/burble`, so the
  registered path was right. The census compared full `git ls-remote` ref
  lists, which match in both directions of a redirect, so it showed that two
  names were one repository but not which name was canonical. `burble` is
  restored to `metadatastician` with its original ids and no archive record.
* `scripts/check-registry.sh` checks the archive: every archived id
  re-derives from its earlier path, generations count 1..n with the current
  one n+1, each entry names a current repository at its current path, and no
  archive data reaches `repos.json` or `index.json`. The test adds a legal
  return to an earlier path and 4 planted archive faults.
* `scripts/check-registry.sh` re-derives both ids for every entry instead of
  spot-checking three. `tests/check-registry-test.sh` plants a tampered
  `uuid_v8` as well. Worker CI installs Bun 1.4.2, sha256-verified, for the
  gate, and `just deps` checks for `bun`.

==== Fixed

* `sync/export-json.sh` no longer writes an empty identifier when `uuidgen`
  is missing or fails. awk's `getline` read the failure as an empty string,
  so the export used to succeed with blank ids. It now stops with an error.
