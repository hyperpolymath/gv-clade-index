= The A2ML files removed from gv-clade-index on 2026-11-14

A2ML is retired (owner rulings D99, D269c, D312, D313): no `.a2ml` file
should exist. Each `.a2ml` file in this repository was translated into deed
form where a mapping spec in standards `1-formats/deed/mappings/` says it
translates, its readers were moved, and it was deleted. A field a spec does
not list does not translate; it was dropped, not re-homed. A file with no
mapping spec was deleted (A7 ruling Q7). This follows the hypatia migration
(hyperpolymath/hypatia#1113).

This record lists each removed file, what it was, and where its content
went. The contents are not copied here. Git history keeps them. To read one,
use its blob id, or read its path at the last commit that held it:

[source,bash]
----
git cat-file -p <blob id>
git show fb1c397d8fb3e571b66a55e66ed65debe7268bbb:<path>
----

Size is in bytes. The sha256 is of the file as it was tracked.

The new deeds are `gv-clade-index_chora.deed` (identity, clade, forges,
lineage, agentic, neurosym, playbook), `.machine_readable/descriptiles/STATE.deed`
(status, maturity) and the pointer-only `0-AI-MANIFEST.deed`. Each passes
`deed_lint.js`; `STATE.deed` also passes `--state --strict` against the chora
deed.

== Removed as one class: the directory manifests

Eighty-one `0.N-AI-MANIFEST.a2ml` files (N from 1 to 4, 25878 bytes in all)
sat one per directory of the scaffold: `.github/`, `.machine_readable/`,
`container/`, `docs/`, `examples/`, `features/`, `src/`, `verification/` and
their subdirectories. They are the scaffold's directory-manifest family,
which `ai-manifest-decision.adoc` section 0 names as a different family from
the root AI manifest, with no mapping spec of its own. Each held a `[META]`
id, level and parent and an `[AI_MANIFEST]` description, sometimes with
`canonical_locations` and template `invariants` (for example "ABI MUST be
Idris2"). None carries a fact about this repository: they are the template's
text, the same in every repo minted from it. Two are a single comment line
(`.github/` and `examples/`). `container/0.1-AI-MANIFEST.a2ml` describes the
stapeln container templates. The `features/` manifests (`boj-server`,
`panic-attacker`, `ssg`) describe the template's optional feature bootstrap
guides, whose `README.adoc` files stay; `panic-attacker` is panic-attack's
old name. All 81 were deleted, untranslated.

== Retained, with the reason

Three `.a2ml` files stay. Each is registry data with a live reader, and each
needs its own mapping spec before it can go; standards
`registry-seed-to-deed.adoc` converted only the seed (`repos.a2ml`) and says
the other two seed files wait for their own conversion.

[cols="3,5",options="header"]
|===
| Path | Why it stays

| `verisim/seed/clades.a2ml`
| The served clade definitions. `sync/export-json.sh` builds
`worker/data/clades.json` from it, the Worker serves that file, and
`scripts/check-registry.sh` checks that scheme `clade-12` in the seed names
the same categories. Its conversion needs its own mapping spec.

| `verisim/seed/forges.a2ml`
| The registry's forge accounts (GitHub primary; GitLab, Bitbucket, Codeberg
and SourceHut mirrors). Registry data, not repo metadata, and named by the
`verisim/seed/*.a2ml` whitespace-lint glob in `worker-ci.yml` and the
Justfile's `fmt` and `fmt-check`. It waits for its own conversion
(`registry-seed-to-deed.adoc`).

| `verisim/config.a2ml`
| The VeriSimDB instance configuration of record: `worker/wrangler.toml`
times its cron against its sync interval, and
`docs/governance/RELEASE-RUNBOOK.adoc` names it as where the instance's
pointer authority, ports and auth are configured. Registry configuration
with no mapping spec.
|===

  the set is extended or each edge is restated in an existing term.

  and golden path need the owner's word.

  from the retired `CLADE.a2ml`; it moves to `chora-registry_chora.deed` when
